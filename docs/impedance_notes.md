# インピーダンス制御(コンプラ制御)の試しで分かったこと

FR3 実機(コントローラ Web 3.9.7 / QNX 部品 V3.9.33-qx、SDK v2.3.7)で、2026-11-11〜18 に試した結果。
GUI の使い方は [gui_usage.md](gui_usage.md)。

## 結論
- **インピーダンス制御は、軌道(動き)があるときだけ効く。** 止まったまま開始しても、押して譲らない。
  - Web のプログラム(自動モード)でも、GUI(SDK)からでも同じ。
  - マニュアル 9.33 の「動いている軌道に対して効く」とも合う。
- 確かめるときは「**開始 → 動き → 終了**」の形にする。止まった状態の代わりには、小さな行き来を続ける(GUI の「今の位置を保持して、インピーダンス制御を確かめる」)。
- **インピーダンス中は、手先の直線移動(SDK の MoveL)は受け付けられる(戻り値 0)が、腕が動かない。関節移動(MoveJ、Web の PTP)は動く**(2026-11-18、SDK のログで確認)。GUI は、インピーダンスを入れた移動を関節移動に直して送る。
- 剛性 k = 0 では、押されてずれたあと戻らない。戻すには k > 0 が要る(未試験)。

## 試した結果
| 試し | 軌道 | 押したとき |
|---|---|---|
| Web: 開始 → WaitMs(30000) → 終了(2 回、同じ設定・同じ押し方) | なし | 譲らない |
| Web: 開始 → PTP で左右に行き来 → 終了 | あり | 譲った |
| GUI(SDK): 開始だけ | なし | 譲らない |

設定はどれも関節空間、閾値 10,10,10,1,1,1、m 0.04×3・0.01×3、b 0.1×3・0.08×3、k 0、最大速度・加速度 10。

## Web のプログラムで動いた形
```lua
ImpedanceControlStartStop(1,0,{10,10,10,1,1,1},{0.04,0.04,0.04,0.01,0.01,0.01},{0.1,0.1,0.1,0.08,0.08,0.08},{0,0,0,0,0,0},10,10,10,10)
WaitMs(1000)
PTP(test,5,-1,1,0,-50,0,0,0,0)
PTP(test,5,-1,1,0,100,0,0,0,0)
PTP(test,5,-1,1,0,-50,0,0,0,0)
PTP(test,5,-1,1,0,100,0,0,0,0)
PTP(test,5,-1,0,0,0,0,0,0,0)
WaitMs(10000)
ImpedanceControlStartStop(0,0,{10,10,10,1,1,1},{0.04,0.04,0.04,0.01,0.01,0.01},{0.1,0.1,0.1,0.08,0.08,0.08},{0,0,0,0,0,0},10,10,10,10)
```
- `ImpedanceControlStartStop(開始1/終了0, 空間 0=関節・1=直交, 閾値, m, b, k, 最大速度, 最大加速度, 最大角速度, 最大角加速度)`
- `PTP(点, 速度%, -1, ずらす座標, dx, dy, dz, drx, dry, drz)`: ずらす座標を 1 にすると、ベース座標で y に動いた(4 番目の意味は推測。マニュアルでは未確認)。
- 点 `test`: 関節 [0.86, -92.45, 80.85, -73.04, -91.16, -100.97]、手先(ツール 1)[-304.6, -102.5, 263.5] mm。

## Web のプログラムの注意
| 起きたこと | 原因(推測を含む) | 避け方 |
|---|---|---|
| 開始の 0.2 秒後に「軸1関節空間内指令速度リミット超過」 | 開始の直後に、長さ 0 の PTP(今いる点へ、ずらさない) | 開始のあとに `WaitMs(1000)`。長さ 0 の PTP を置かない |
| 開始の 6 秒後に「軸4関節空間内指令速度リミット超過」 | 最大角速度・最大角加速度を 0 にした(手首の速度の上限に使われる疑い)。j4〜j6 の b を 0.04 にした | 4 つの最大値は、すべて 0 より大きくする |
| GUI(SDK)で、押されてずれたあと、インピーダンス中に同じ目標へ MoveJ を送り直したら、故障 1-26、その後の命令はすべてエラー 14 | インピーダンスのずれは指令(目標)の上に乗っているので、同じ目標への移動は指令の上では長さ 0 になる(推測) | 同じ目標へは送らない。目標の ± 少しの点へ交互に送ると、ずれが戻る |
| GUI の「今の位置を保持」で、行き来の幅を 0.001° にして押したら、故障 1-23 | 行き来がほぼ長さ 0 の移動になるため(推測)。0.3° では押しても故障しなかった | 行き来の幅は `hold_amp_min_deg`(0.1°)以上。0.1° で押して大丈夫かは未確認 |
| 最後の PTP の途中で止まる | 動きの命令は先読みされ、終了の行が先に実行される | 最後の PTP のあとに `WaitMs` を置く |
| 三角(▶)が押せない | Web のプログラムは自動モードでしか実行できない | 自動モードにする |
| 「ステップ実行指令下達失敗」 | 手動モードの 1 行ずつの実行で、インピーダンス開始の行は実行できない | 1 行ずつの実行に使わない |
| 押すと「手動モードに切り替えてください」 | フランジ近くのボタン(DI1、ティーチングポイントの記録)に触れた疑い | ボタンを避けて、ひじ寄りの腕を押す |
| 静止状態で、+Y に押したときだけ譲った | 静的衝突検知(衝突レベル 10)の働き。インピーダンスではない | インピーダンスを試すときは、静的衝突検知を OFF |

## 値を変えるとき
| ねらい | 変える値 |
|---|---|
| より軽い力で譲る | 直交空間にする(閾値 30 N ≒ 3 kg。関節空間の j1 は手先で 6〜7 kg 相当)、根元から遠いところを押す |
| 動き出しを軽く(プランプラン) | m を小さく(半分など)、j4〜j6 の b を小さく(振動に注意) |
| 離したら戻る | k を 0 より大きく(範囲・単位の記載なし。小さい値から) |
| 速く戻る | 最大速度・加速度を上げる(実機は常にゆっくりの約束があるので、上げる前に相談する) |

1 回に 1 つだけ変えて、違いを確かめる。

## まだ分かっていないこと
- 2026-11-11 に GUI(SDK)で、止まった状態で j1 約 22 N·m で譲ったように見えた。そのときのモード・静的衝突検知の設定が記録になく、インピーダンスだったかは不明。
- 手動モードと自動モードで、効き方が違うか。
- k > 0 で、どのくらいの速さで戻るか。
